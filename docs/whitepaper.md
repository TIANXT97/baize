## 摘要(Executive Summary)

白泽(Bai Ze)在 v1.5.1 的双端前置判别门控基础上,于 v1.5.2 完成流式检索改造,解决长生命周期 Agent 记忆库数据增长(突破 6.6 万条事实、3.2 万条向量)带来的 CPython 堆内存膨胀与页缓存沉淀问题。

本版本完成了底层的**游标流式分块(fetchmany streaming)与全局页缓存硬上限**改造:
1. **向量检索游标流式化(内存削减 46%)**:废止全量 `fetchall()` 反序列化 3.2 万个 Python 字典对象,改为 `cur.fetchmany(2000)` 分批流式消费。每批仅保留轻量标量元组并即时释放,在召回结果完全一致的前提下,日常常驻内存(RSS)稳定在 **75MB ~ 80MB**;
2. **SQLite 页缓存与 mmap 硬约束**:全局连接统一设置 `PRAGMA cache_size = -1000`(单连接上限 1MB)与 `PRAGMA mmap_size = 0`,抑制 Linux 脏页沉淀;
3. **即时内存回收(malloc_trim)**:检索结束后显式调用 `malloc_trim(0)`,归还瞬态堆碎片;
4. **压力测试验证**:通过 12 线程混合并发读写(0 次死锁)与连续 50 轮全库 3.2 万向量密集检索,内存在高压后稳定回落,未观察到泄漏。

## 一、 系统定位与架构全景

### 1.1 核心设计原则
1. **轻量自托管**:纯 Debian 13 环境,零外部依赖(无 JVM、无分布式 etcd/MinIO/Pulsar),单进程原生 Python + SQLite WAL,常驻端口 `8767`,日常常驻内存 **75MB ~ 80MB**,毫秒级响应。
2. **写入过滤、召回门控**:
   - **写入端**:Jev 前置判别拦截纯闲聊与无持久价值的过渡句,保护知识库纯度;
   - **召回端**:Jev 语义意图判别配合关键词白名单直通,仅在需要时检索记忆。
3. **流式消费与严格有界**:不将全量大表或批量对象常驻内存,高频数据处理以 2000 为步长流式迭代,处理完即释放。
4. **结构化约束优先于提示词约定**:不依赖 LLM 自行判断是否推测,而是在输入解析层按角色机械打标,非用户亲陈事实在代码层不允许进入 CoreMemory。
5. **耐久性优先**:应用层 WAL 经过 `f.flush()` 与 `os.fsync()` 写穿内核页缓存,确认落盘后才视为成功。

## 二、 核心机制与技术实现

### 2.1 游标流式消费与页缓存上限(v1.5.2)
- **向量检索游标流式消费**:
  - 在 `modules/hybrid_recall.py` 的 `_vector_search_i8` 中,废止一次性 `fetchall()`,改为 `cur.fetchmany(2000)` 分块拉取。
  - 每批过滤异常 blob 后立即转为连续 numpy 矩阵计算余弦,仅收集轻量 `(mem_id, score)` 标量;
  - 循环中显式 `del batch` 释放原始对象,循环结束后统一用 `np.argpartition` 取 Top-k。
  - 检索返回前调用 `ctypes.CDLL("libc.so.6").malloc_trim(0)`,回收堆内存碎片。
- **SQLite 缓存与内存映射上限**:
  - 全局连接统一设置 `PRAGMA cache_size = -1000;`(单连接页缓存上限 1MB)与 `PRAGMA mmap_size = 0;`(关闭 mmap),避免内核脏页常驻。

### 2.2 双端前置判别门控(Jev Gate & Memory Gate)
- **写入端前置快筛**:
  - 调用主门控 OpenJev 0.1(26B)判别文本的长期记忆价值(`threshold=0.25`);主门控超时、HTTP 异常或返回无效 `answers` 时,自动切入备用门控 Drex v2.0(3B MoE)接管。判定为 `ephemeral` 的闲聊直接返回,降低 Token 消耗。WAL 重放路径强制绕过门控。
- **召回端检索门控**:
  - 纠正信号与显式口令走 0ms 白名单直通;主/备门控做语义意图判别(`search_threshold=0.35`);主备均失效后走 HF Laya 兜底(携带代理与统一 User-Agent),最终以正则 Fail-open 放行。
- **白名单**:`jev_gate.py` 读取 `custom_whitelist` 配置项,默认仅含通用工程词;用户可在 `config.json` 中按需追加。

### 2.3 认知安全与墓碑防御
- **Origin 身份硬隔离**:非用户亲陈事实禁止同步进入 `user_profile`;
- **极性反转取代**:否定词翻转直接判定 `replaces`(置信度 0.85),通过主题词覆盖判定极性,避免长句并集稀释;
- **被否决事实墓碑(rejected_values)**:废弃事实的 SHA-256 写入墓碑,换 ID 或微调语序仍会被拦截;
- **生肉回灌硬熔断**:提取结果为空时不落盘,超长文本与动作描写强制拒签。

### 2.4 排他存储事务
- `get_db(write=True)` 执行 **`BEGIN IMMEDIATE`** 提前获取写锁,消除读升写死锁;
- `wal.py` 写入后执行 `os.fsync()` 写穿内核页缓存。

## 五、 v1.5.3 检索与提取修复

在 v1.5.2 完成内存优化之后,v1.5.3 针对长期检索的数学单调性、SQLite 边界条件与无主记忆提取三个方面做了修复:

1. **SQL 三值逻辑修复 (`NOT EXISTS`)**:
   - 在 `hybrid_recall.py` 中,旧逻辑 `m.id NOT IN (SELECT memory_id FROM memory_states WHERE state = 'superseded')` 存在 SQLite 三值逻辑缺陷——子查询结果中只要出现一个 `NULL`,`NOT IN` 整体判定为 `UNKNOWN`,导致全库有效事实被错误过滤;
   - 现改为 `NOT EXISTS (SELECT 1 FROM memory_states s WHERE s.memory_id = m.id AND s.state = 'superseded')`,不受 NULL 影响。

2. **L2 距离单调指数映射**:
   - 弃用容易越界或产生负分的线性截断 `max(0, 1 - d / 2.0)`;
   - 改用指数映射 `score = math.exp(-d / 0.8)`,保证得分在 `(0, 1]` 区间内严格单调递减。

3. **时效增益由加法改为乘法**:
   - 废除固定加分(`+0.25` / `+0.15`),避免无相关性的新内容仅凭时效超过高相关的历史记录;
   - 改为相对乘性增益 `score *= (1.0 + alpha)`(24h 内 α=0.10,48h 内 α=0.06),时效只对本身相关的事实同比例提升。

4. **提取端锚词质检**:
   - `llm_extract.py` 新增 `_extract_anchors()`,抽取原文中的组件名、版本号、端口范围与专有代号;
   - 若提取结果丢失原文锚词(退化为“用户拥有三个账号”类无主泛化句),触发一次带纠偏指令的重试,重试仍保留 Fail-open 兜底。

5. **WAL 容灾与降级事实**:
   - `wal.py` 写入操作全面引入 Fail-open,fsync 异常仅记录警告,不阻断业务;归档文件名追加毫秒时间戳与 UUID,避免并发重名覆盖;
   - 提取链失败时自动记录 `raw_fallback`;`raw_fallback` 写入时赋 `expires_at = now + 7d`,AutoDream 周期巡检清理过期降级事实并同步删除向量。
